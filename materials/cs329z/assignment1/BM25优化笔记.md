# BM25 建索引与查询优化笔记

记录日期：2026 年 10 月 23 日。第三题已经完成基本实现；本笔记记录独立性能实验，不代表整份 HW1 已完成。原作业实现保留在 `assignment1-harness/cs329z_hw1/adapters.py`。

## 本次实测

同一台电脑，26,278 封邮件、17 个课程查询；文件加载不计入时间。建索引取 3 次中位数，查询取预热后 7 批平均查询耗时的中位数。

| 实现 | 建索引 | 平均查询 |
|---|---:|---:|
| 原字典实现 | 2.282 秒 | 4.722 毫秒 |
| 自写 NumPy 预计算实验版 | 2.556 秒 | 0.466 毫秒 |

实验版查询快约 10.1 倍，建索引慢约 12%。全部 18 项原测试通过，Recall@10 为 1.000；17 个查询的前 50 篇文档顺序及分数与原版一致。

之后改为直接调用上游 BM25S，用户报告查询约 0.2 毫秒，建索引仍为 2 点几秒。这是另一次终端观察，未按上表相同的重复计时方式统计。单位是**毫秒，不是纳秒**。

## 为什么查询能更快

设 N 为文档数，T 为全部词项数，P 为查询词命中的倒排记录数，M 为候选文档数，K 为返回条数。

1. **预计算每个词对每篇文档的贡献。** 固定语料、k1、b 后，单词贡献不依赖未来查询，可在建索引时计算；多词查询只需相加。不会把 P 条记录变少，但减少每次查询重复计算公式的开销。更新语料导致 IDF 或平均长度变化时，需要更新这些预计算值。
2. **用紧凑数组替代嵌套字典。** 保存文档编号、贡献分和词对应的区间；提高数据局部性，减少 Python 对象开销。NumPy 向量化主要降低执行常数，不自动改善复杂度。
3. **只选择前 K，再排序 K 项。** 完整排序为 O(M log M)；部分选择加小范围排序可达 O(M + K log K)。同分截断必须按文档编号处理，否则可能与课程要求不一致。
4. **保留只访问命中文档的优势。** 稀有词只命中三篇时，不应在 Python 中遍历整个文档库。上游 BM25S 的 NumPy 路径仍构造全库分数数组；其实际速度优势不等于整个查询复杂度只依赖 P。

我们的原查询约为 O(P + M log M)。自写 NumPy 实验版的多词合并使用 `np.unique` 排序去重，带有 O(P log P) 开销，不能称为整体线性算法。它在本次数据上更快，主要得益于预计算和底层数组运算。

BM25S 属于计算方式优化；本实验保持课程要求的评分公式，不通过更换 BM25 变体改变结果。

## 如何让建索引更快

**算法层面：** SPIMI（单遍内存建索引）边读取词项边追加倒排记录，避免先收集全部“词—文档”记录再进行全局排序。内存内构建在哈希操作预期常数时间的前提下可达 O(T)。大规模分块落盘还需考虑字典排序、合并和 I/O 成本。

当前字典实现已经接近这一思路：每个词项处理一次，预期为 O(T)。完整索引需要读取全部输入，因此进一步优化通常降低常数或使用并行计算，而非再降低复杂度阶数。

可以逐项尝试，效果必须测量：

- 每篇分词后立即计数并写入倒排表，避免保存整个 `tokenized_docs` 副本及后续遍历。
- 用 `Counter` 统计篇内词频，再按不同词写入记录，减少重复字典查找。
- 减少临时列表、字典和不必要的数据类型转换；最终需要数组时集中转换。
- 数据规模更大时考虑多进程分片构建后合并；进程启动、数据传输、合并都有成本，不能假定本作业一定更快。
- 若分词占主要耗时，再研究更快且与课程规则完全一致的实现；不能为了速度改变大小写、标点、重复词的处理方式。

预计算贡献分本身会给建索引增加工作，是用一次性成本换反复查询速度。不能要求它必然同时加快建索引。

## 实验文件与运行方式

以下路径均相对项目根目录：

- `assignment1-harness/experiments/bm25_numpy.py`：自写 NumPy 实验版。
- `assignment1-harness/experiments/compare_bm25.py`：原版与自写实验版重复计时及结果比较。
- `assignment1-harness/experiments/bm25_upstream.py`：直接调用上游库的适配层。
- `assignment1-harness/tests/test_bm25_github.py`：复用课程全部 BM25 测试，替换为上游适配层。

在 `assignment1-harness` 目录运行原版：

```bash
uv run pytest tests/test_bm25.py -v -s
```

运行上游库实验：

```bash
uv run --with bm25s==0.3.2 pytest tests/test_bm25_github.py -v -s
```

适配层使用课程分词器、查询词去重、无匹配过滤和文档编号同分排序。上游设置 ATIRE 词频分量配合 Lucene IDF，以匹配课程含 `(k1 + 1)` 的公式；使用 float64。上游库仅用于独立比较，不作为作业提交实现，项目依赖文件未改。
